## 13:10 작업
**요청:** 이 앱에서 "MIDI 내보내기"로 만든 미디 파일을 다시 불러올 수 있는지 문의. `midi.ts`를 확인한 결과 내보내기는 코드·패턴·섹션 같은 구조화 데이터 없이 "연주된 음표"만 SMF로 찍어내는 방식이라, 완전 복원은 사실상 불가능함을 설명하고 범위를 질문 → "부분 추출(코드 진행 근사 + 템포, 패턴은 장르 기본값)"로 답변받음.
**작업 내용:**
- `packages/core/src/midiImport.ts` 신규: 표준 MIDI(SMF format 0/1, PPQ 방식) 파서를 직접 구현(헤더·트랙 청크, 가변길이 델타타임, 러닝 스테이터스, 템포 메타 이벤트 0x51 읽기). 드럼 채널(10번, 인덱스 9)을 제외한 노트온 이벤트를 박자(quarter note) 단위로 묶어 피치클래스 집합을 만들고, 모든 (근음×코드 성질) 조합에 대해 겹침 점수를 매겨 가장 가까운 코드 기호를 고르는 방식으로 코드 진행을 근사 추정(`bestChordSymbol`/`scoreChord`). 연속된 같은 코드는 하나로 합치고, 섹션 제한(`SONG_LIMITS`)을 넘으면 앞부분만 자르거나 뒤를 마지막 코드에 합치며 경고 메시지를 남긴다. 템포는 메타 이벤트에서 BPM으로 환산(40~240 범위로 clamp). 비트·악기 패턴은 MIDI에 없으므로 `generateSong`으로 만든 해당 장르의 기본 패턴을 그대로 재사용. 최종적으로 `validateSong`으로 검증 후 `{ ok, song, warning? } | { ok: false, error }` 형태로 반환(기존 `songfile.ts`의 `ParseResult` 패턴과 동일한 스타일).
- `packages/core/src/midiImport.test.ts` 신규: 빈 파일·비(非) MIDI 파일 오류 처리, 이 앱이 내보낸 MIDI를 다시 불러왔을 때 유효한 곡이 되고 BPM이 보존되는지(라운드트립), 드럼만 있고 음높이 트랙이 전부 음소거된 MIDI는 "코드를 찾지 못했다" 오류를 내는지 검증.
- `packages/core/src/index.ts`: `export * from "./midiImport"` 추가.
- `apps/studio/src/App.tsx`: "곡 불러오기" 버튼 옆에 "MIDI에서 코드 가져오기" 버튼과 숨은 `<input type="file" accept=".mid,.midi,...">` 추가. 선택한 파일을 `midiToSong(bytes, { genre, title })`에 넘기고, 실패하면 기존 `fileError`에, 성공하면 "추정치이며 패턴은 장르 기본값"이라는 안내를 새 `midiNote` 상태에 표시. 편집한 내용이 있으면 기존 불러오기 버튼들과 동일하게 `window.confirm`으로 먼저 확인.
**결과:** 완료 — `npx tsc --build` 통과, `npx vitest run` 154개 테스트 전부 통과(신규 4개 포함). 브라우저로 직접 라운드트립 확인: "MIDI 내보내기"로 로파이 샘플 곡(Cm7-F7-Bbmaj7 진행 포함, 52마디 상당)을 내보낸 뒤 그 파일을 "MIDI에서 코드 가져오기"로 다시 불러오니, 안내 문구("추정치, 정확하지 않을 수 있어요" + "코드 변화가 많아 일부는 이전 코드로 합쳐졌습니다")가 뜨고 새 섹션 "가져온 코드"(52마디)가 생성되어 Cm7·F11·F13/A# 등 원곡과 비슷하지만 완전히 같지는 않은 코드 진행으로 복원됨을 확인 — 설계대로 "근사치"로 동작. 콘솔 에러 없음(기존에도 있던 무관한 404 리소스 1건 제외).
