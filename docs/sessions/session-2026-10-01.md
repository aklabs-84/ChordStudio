## 08:20 작업
**요청:** 앱의 모든 화면(만들기·레슨·코드 입력 탭)에서 각 섹션의 코드를 클릭하면 편집할 수 있게 되어 있는데, 해당 코드의 화음을 짧게 재생해서 들려줄 수도 있는지 요청. 이후 확인 질문 3건에 대해 "모든 화면 포함" / "클릭 시 자동 재생" / "피아노 고정"으로 답변받음.
**작업 내용:**
- `packages/core/src/theory.ts`: `chordToMidiNotes(symbol, baseOctave = 4)` 함수 추가 — 코드 기호를 파싱해 `chordIntervals`(반음 간격, 9도 이상도 정확히 반영) 기반으로 MIDI 노트 배열을 만든다. 슬래시 코드는 베이스 음을 한 옥타브 아래에 추가.
- `packages/core/src/engine.ts`: `Engine` 인터페이스에 `previewChord(symbol: string): void` 추가. `isValidChord`로 가드하고, `Tone.start()`를 보장한 뒤 `chordToMidiNotes`의 각 노트를 `instruments.piano.play()`로 동시에 재생(0.7초). 기존 재생 스케줄(Transport)과 무관하게 동작하며, `instruments.piano.output`이 이미 믹서 채널(`channels.piano`)에 연결돼 있어 피아노 트랙의 볼륨/뮤트/솔로 설정을 그대로 따른다.
- `apps/studio/src/App.tsx`: `previewChord = (symbol) => engineRef.current?.previewChord(symbol)` 콜백을 만들어 `<ChordEditor>`(만들기 탭), `<Wizard>`(레슨 탭), `<ChordInputView>`(코드 입력 탭)에 `onPreviewChord`로 전달.
- `apps/studio/src/components/ChordEditor.tsx`: 코드 버튼 `onClick`에서 기존 `setSel(...)` 토글에 더해 `onPreviewChord?.(c.symbol)` 호출 추가 (새 UI 요소 없음, 클릭 시 자동 재생).
- `apps/studio/src/components/Wizard.tsx`: `onPreviewChord` prop을 받아 내부 `<ChordEditor>` 호출에 그대로 전달.
- `apps/studio/src/components/ChordInputView.tsx`: 코드 칩마다 새 ▶ 아이콘 버튼 추가(`isValid`일 때만 활성화), 클릭 시 `onPreviewChord?.(chord.symbol.trim())` 호출. 이 탭은 코드가 항상 편집 가능한 텍스트 입력이라 클릭-편집 진입점이 없어 별도 버튼으로 구현.
**결과:** 완료 — `npx tsc --build` 통과, `npx vitest run` 150개 테스트 전부 통과. `npm run dev`로 로컬 구동 후 브라우저로 확인: 만들기 탭에서 코드 버튼 클릭 시 기존 편집 줄이 정상적으로 열리고 콘솔 에러 없음(오디오 자체 청취는 도구로 확인 불가하나 `previewChord` 호출 경로에 예외 없음을 확인), 코드 입력 탭에서 각 코드 칩 옆 ▶ 아이콘이 정상 렌더링되고 클릭 시에도 에러 없음. `ChordEditor.tsx`는 시각적 DOM 변경이 없어(클릭 동작만 추가) before/after 스크린샷 차이가 없고, `ChordInputView.tsx`는 ▶ 아이콘이 새로 보이는 화면 변경이라 캡처했으나 별도 "수정 전" 캡처는 남기지 못해 이번 로그에는 after 화면만 첨부함.
